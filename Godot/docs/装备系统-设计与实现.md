## 1. 目标与边界

**做什么**

- 从 Lua 配置表导出装备数据，建立可查询的装备数据库；
- 实现 21 个装备栏位、穿戴/卸下规则（等级/主属性/性别/腕力/负重/不可卸下）；
- 实现装备属性汇总（计数器模型，与 Lua 的 `m_CounterEquip` 对应）；
- 实现**人物外观拼接**：部件贴图槽 31-47 重定向 + 武器/翅膀/发型挂到附着点；
- 提供一个可交互的装备界面与演示场景；
- 用 headless 自检证明上述规则与 Lua 一致、且拼接出来的资源路径真实存在。

**不做什么**（明确留白，避免误以为已实现）

- 强化 / 祝福 / 淬炼 / 进阶 / 圣化 / 开光 / 幻灵 / 镶嵌 / 鉴定 / 打造 / 词缀洗练的**数值公式**；
  界面里强化与星级是两个演示用按钮（直接改等级看外观层），不是真实的成功率与消耗。
- 背包容量、负重上限、掉落、交易、存档（`clsSaveManager2.lua`）等外围系统。
- 服务端权威同步：本模块是单机/预览语义，没有任何网络契约。

## 2. 数据流

```
D:\rpg\output\lua_ref_src\script\const1.lua        ─┐
D:\rpg\output\lua_ref_src\script\setting\ShapeCfg.lua ├─> Godot/tools/lua_equip_export.py
D:\rpg\output\lua_ref_src\script\setting\ItemCfg.lua  ─┘        │
                                                                  v
                        Godot/equipment/Data/{constants,shapes,items}.json
                                                                  │
                                            EquipDatabase.Load("res://equipment/Data")
                                                                  v
   HeroProfile + EquipLoadout ──> EquipLookBuilder ──> EquipLook ──> HeroAvatar ──> MdxAssetLibrary / MdxModelNode
```

导出（Python 3，纯标准库；内置一个只认数据表的 Lua 表解析器）：

```powershell
python Godot/tools/lua_equip_export.py
# 可选：--lua-dir <script 目录>  --out <输出目录>
# 当前产物：constants.json 19 KB / shapes.json 238 KB / items.json 1.1 MB
# 统计：栏位 21，物品类型 79，外观 803，装备 1275，外观缺失 0
```

要点：

- `ShapeCfg.lua` 是**数组表**（`[1]={...}`）并混有 `FXList`/`HairColor` 等旁表，解析器按"数字键→外观条目"筛选；
- `ItemCfg.lua` 顶层还有 `ItemMapId`/`ItemNameMap` 等旁表，同样按"整数键 + 含 ItemType"筛选；
- **ItemCfg 里没有 Mdx/StrType**：模型数据全在 `ShapeCfg`，靠 `ItemCfg[X].Shape` 关联；导出时已把外观内联成 `item.look`；
- `const1.lua` 是语句式赋值（含 `const.A.B = v`、`const.A[const.C] = {..}`），解析器逐条求值并支持常量互相引用。

## 5. 穿戴规则（`EquipLoadout.CanEquip`）

按 `clsMouseManager.lua:991-1007` + `clsItemManager.lua:2066-2131` 的顺序：

1. **栏位匹配**：`EQUIP_POS2TYPE[栏位] == 物品 ItemType`，否则"不能装备在这个位置"；
2. **需求**：`NeedType` 1 等级 / 2 攻击 / 3 魔法 / 4 道术 / 5 弓术 / 6 刺术 / 7 转生，与 `NeedValue` 比较；
3. **性别**：仅衣服/裤子带 `Sex`（1 男 2 女）；
4. **腕力**：武器比 `Heavy` 与 `HeroProfile.HandHeavy`；
5. **负重**：非武器累计 `Heavy`，换装时先扣掉被换下件，再与 `HeroProfile.BodyHeavy` 比较；
6. **被换下件不可卸**：`EQUIP_STATE_NOOFF(2)` → 拒绝。

职业（`JobTag`）在 Lua 里**穿戴时不校验**（只有神鼎提交时校验），因此 `EquipmentOptions.EnforceJobTag` 默认 `false`，
需要更严格的玩法时再打开。`EquipmentOptions` 其余开关同理（`EnforceSex`/`EnforceWeight`/`EnforceRequirement` 默认开）。

状态位沿用 Lua：`1` 诅咒(名字带"(诅咒)")、`2` 不可卸下、`4` 已鉴定、`8` 锁定。

## 6. 外观拼接（`EquipLookBuilder`）

### 6.1 部件贴图槽（`SetUnitTexture` 等价物）

| 部件 | 栏位 | 主槽 | 强化层 | 星级层 | 贴图来源 |
|---|---|---|---|---|---|
| 裤子 | Trousers | 31 | 36 | 44 | `rw\{Path1(男)/Path2(女)}.blp` |
| 护手 | Glove | 32 | 37 | 45 | 同上 |
| 鞋子 | Shoes | 33 | 38 | 43 | 同上 |
| 衣服 | Cloth | 34 | 39 | 46 | 同上 |
| 披风 | Cloak | 35 | 40 | 47 | `rw\{Path}.blp`（不分性别） |

- 强化层 = `const.WEAPON_STRONG_PATH[职业][强化等级]`（`const1.lua:1083-1193`），无则 `rw\rw_touming_SMINAD.blp`；
- 星级层 = `const.EQUIP_STAR_PATH[职业][星级]`（`const1.lua:1194-1304`），无则 `rw\rw_touming2_<部件>_SMINAD.blp`；
- 两个表都只有 1..20 档（第 8 档起复用第 7 档），等级 0 视为"无"，直接给透明件；
- **空栏回退**：没穿该部件时用裸装外观（`clsUnitHero.lua:1863-1879`）—— 衣服 20、护手 30、裤子 40、鞋子 50、披风 60。

### 6.2 挂件

| 挂件 | 附着点 | 模型 | 附加贴图 |
|---|---|---|---|
| 武器 | `hand left` / `hand right` | `wq\{Mdx}.mdx` | 强化 41 / 星级 42 |
| 翅膀 | `chest` | `cb\{Mdx}.mdx` | — |
| 发型 | `head` | `shape\{Mdx}.mdx` | 发色 99（未实现） |

`HandState` 语义（`clsUnitHero.lua:1837-1847`，照抄、不做"修正"）：

- `1` → 左手；`2` → 左右手各一件；`3` → `hand left` 主手 + `hand left` ExMdx 副手；其他 → 右手。

### 6.3 与 WC3 的对应关系

WC3 的 `SetUnitTexture(handle, path, id)` / `AddSpecialEffectTarget(model, path, attach)` 在本模块里是：

| WC3 | 本模块 |
|---|---|
| `SetUnitTexture(..., id)` | `MdxAssetLibrary.SetReplaceableOverride(id, Texture2D)` + `MdxModelNode.RebuildMaterials()` |
| `AddSpecialEffectTarget(..., attach)` | `MdxModelNode.AttachToAttachment(Node3D, attach)`（每帧跟随骨骼） |
| 附着点名查找 | 先精确匹配，再**不区分大小写的包含匹配**（`"hand left"` 命中 `"Hand Left Ref"`） |

> 人物模型 `rw\rw_nan_SMINAD.mdx` 的实际附着点：`Chest Ref / Hand Fourth Left Ref / Hand Fourth Right Ref /
> Hand Left Ref / Hand Right Ref / Head Ref / Origin Ref / Overhead Ref`。
> TEXS 里的替换贴图 ID 正是 31-35（部件）、36-40（强化）、43-47（星级）——没有 41/42，因此武器的 41/42 与本体不冲突。

## 7. 插件（addons/mdx_preview）的两处扩展

装备系统需要在"运行时按 ID 换贴图"和"把模型挂到骨骼上"，因此给插件补了两个公开 API：

```csharp
// runtime/MdxAssetLibrary.cs
public void SetReplaceableOverride(uint id, Texture2D texture);   // 覆盖表优先于所有源查找
public void ClearReplaceableOverrides();
public bool TryGetReplaceableOverride(uint id, out Texture2D texture);
// LoadTexture 里新增：解码失败的资产记入 _failed 后不再重复解码/告警

// runtime/MdxModelNode.cs
public bool AttachToAttachment(Node3D child, string attachmentName, Vector3 offset = default);
public void DetachAttachmentChild(Node3D child);
public void DetachAllAttachmentChildren();
public bool TryGetAttachmentTransform(string attachmentName, out Transform3D transform);
public int SetSequenceByName(string sequenceName);   // -1 表示没有该序列
```

`AttachToAttachment` 挂上去的节点在 `MdxModelNode._Process` 的 `UpdateAttachmentChildren()` 里跟随骨骼，
位置由 `MdxInstance.CollectAttachmentPoses()` 的 pivot 决定、朝向由所属骨骼的世界变换决定。

## 9. 扩展指引

- **加一个新栏位/类型**：只改 `constants.json`（或 Lua 后重跑导出）与 `EquipSlot`/`EquipItemType` 枚举；
  中文名、栏位映射、Icon 都会自动跟上。
- **加一个新部件外观**：在 `EquipLookBuilder.Parts` 里加一行（栏位 + 三个槽位 + 裸装 id + 透明件），
  再在 `HeroAvatar` 无需改动。
- **接真实强化系统**：`EquipItem.StrongLevel/StarLevel` 已经是外观层的输入；
  成功率与消耗请按 `clsEquipStrongObj.lua:36-43` / `StrongCfg.lua` 实现，并注意上面提到的 `STRONG_MASK` 伪影。
- **属性生效**：目前 `EquipStats` 只做"计数器求和"（对应 Lua 的 `m_CounterEquip`）。
  Lua 的二次聚合（`Per*` 百分比、上限封顶）在 `clsUnitAttr.lua:3-55`，需要时可移植成 `EquipStats` 的派生查询。
